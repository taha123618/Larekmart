## 2025-05-18 - Client-Side API Batching for N+1 Resolution Requests
**Learning:** Found an N+1 API call bottleneck specific to this codebase's architecture where resolving custom media references (like `media:<uuid>`) was happening completely un-batched in the storefront. Components like `MediaImage` resolved references independently upon mount. For a product grid rendering 24 items, this triggered 24 separate HTTP POST requests to the `media-service` backend exactly at the same time.
**Action:** Implemented a DataLoader-style asynchronous micro-batching mechanism inside `media.service.ts`. By capturing concurrent `resolveMediaUrl` calls into an array and using a short 50ms `setTimeout` to group them, the client now fires a single batched POST request containing a unique set of IDs. This drastically reduces the number of connections and unblocks the main thread overhead. Future implementations doing multiple remote ID resolutions should employ this batch queue approach by default.
